# V2代码重构计划

## 当前问题总结

### 1. 代码重复问题
- **数据集模块**: 4个不同的BddDataset实现
- **损失函数**: 多处重复定义相同的损失函数
- **工具函数**: letterbox、convert_bbox等函数多处重复

### 2. 接口不统一
- NUMBER_IMAGE参数在不同数据集中处理方式不同
- 损失函数接口不一致（core/loss.py vs models/losses/）
- 模型构建方式不统一

### 3. 代码组织混乱
- 存在大量备份文件（.backup）
- 功能相似的模块分散在不同目录
- 缺少清晰的模块职责划分

## 重构原则

1. **保持向后兼容**: 确保现有实验可以继续运行
2. **渐进式重构**: 每次只改动一个模块
3. **充分测试**: 每个改动都要进行测试验证
4. **文档更新**: 及时更新相关文档

## 预期收益

1. **代码量减少30-40%**: 消除重复代码
2. **维护成本降低**: 统一接口，减少维护点
3. **扩展性提升**: 更容易添加新模型和新功能
4. **开发效率提升**: 清晰的代码结构，更快的开发速度
